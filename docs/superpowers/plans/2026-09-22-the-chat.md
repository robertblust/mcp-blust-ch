# The Chat Deployment Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the chat from `companygraph/chat-server` v0.1.0 beside the MCP host in each of the two deployments, `robertblust/mcp-blust-ch` and `companygraph/mcp-companygraph-io`, so that `chat.blust.ch` and `chat.companygraph.io` answer, fenced at CHF 30 a month each.

**Architecture:** Each deployment repository gains a `chat/` directory holding what is its own for the chat (the pin, `chat.json`, the Dockerfile, the brand, the stylesheet, the tests), an `infra/chat/` root of one file calling the chat server's Terraform module with its own state prefix in the project's existing bucket, and a `chat.yml` workflow calling the chat server's reusable workflow. The MCP host's files are untouched except `deployment.json`'s budget. The chat's first deploy fails at its live check by design until `run_host` is written; the second passes. The owner's steps, which Terraform cannot do, are written in each README.

**Tech Stack:** `companygraph-chat-server` v0.1.0 (its `deploy/terraform` module, `deployment.yml` workflow and `deploy/tests`), `@robertblust/design` at the deployment's existing pin, Playwright, Terraform 1.9 with google ~> 8.0, GitHub Actions with the project's existing Workload Identity identities.

**Spec:** `companygraph/chat-server`'s `docs/superpowers/specs/2026-09-22-chat-server-design.md`, §6 (what a deployment keeps) and §10 (the order); its README's "Deploying it" section is the contract this plan follows.

## Global Constraints

- The two deployments are the same change with different values. The values table below is the single source; every file names a value from it and nothing typed twice.
- The chat's release is named in three places, `chat/package.json`, `chat.yml`'s `@v0.1.0` and `infra/chat/main.tf`'s `?ref=v0.1.0`, and the chat server's pin test holds them to one.
- `site_id` differs from the MCP host's; `mcp_url` is the deployment's own host at `/mcp`; `origins` are scheme and host only.
- `deployment.json`'s `budget_chf` moves from 10 to 40; nothing else in it changes.
- Every Markdown paragraph is one line; `sh conventions/conventions-check`, `sh conventions/conventions-format check` and `sh conventions/conventions-sync check` exit 0 before every commit.
- Commit messages and pull-request bodies in the git register of `conventions/WRITING.md`: a plain subject under seventy characters, prose paragraphs with no headings or bullets, a `Verified:` line naming the commands actually run, then `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>` on commits and `🤖 Generated with [Claude Code](https://claude.com/claude-code)` on pull requests.
- The pull request is opened and it stops there; merging, the bootstrap-independent owner steps and the rulesets are the owner's.
- `dist/`, `node_modules/`, `.terraform/` are git-ignored at any depth by the root `.gitignore`; nothing built is committed.
- Every `node`, `npm`, `terraform` and `gh` command runs after `export PATH=/opt/homebrew/bin:$PATH`.

- [ ] **Step 6: infra/chat/main.tf**

```hcl
# The chat beside the server: a second root in the same project, with its own state prefix in
# the bucket the bootstrap made, and one call into the module companygraph/chat-server ships.
# The chat's values are chat/chat.json's; the project's are deployment.json's, stated once.
terraform {
  required_version = ">= 1.9"
  required_providers {
    google      = { source = "hashicorp/google", version = "~> 8.0" }
    google-beta = { source = "hashicorp/google-beta", version = "~> 8.0" }
  }
  backend "gcs" {
    bucket = "blust-ch-mcp-tfstate"
    prefix = "chat"
  }
}

locals {
  d = jsondecode(file("${path.module}/../../deployment.json"))
  c = jsondecode(file("${path.module}/../../chat/chat.json"))
}
variable "image" { type = string }

provider "google" {
  project = local.d.project
  region  = local.d.region
}
provider "google-beta" {
  project = local.d.project
  region  = local.d.region
}

module "chat" {
  source         = "git::https://github.com/companygraph/chat-server.git//deploy/terraform?ref=v0.1.0"
  project        = local.d.project
  project_number = local.d.project_number
  region         = local.d.region
  domain         = local.c.domain
  site_id        = local.c.site_id
  mcp_url        = local.c.mcp_url
  origins        = local.c.origins
  month_tokens   = local.c.month_tokens
  run_host       = local.c.run_host
  image          = var.image
}

output "service_url" { value = module.chat.service_url }
output "run_host" { value = module.chat.run_host }
output "hosting_url" { value = module.chat.hosting_url }
output "dns_records" { value = module.chat.dns_records }
```

Run `terraform -chdir=infra/chat init -backend=false -input=false && terraform -chdir=infra/chat validate && terraform fmt -check -recursive infra/chat`. If `infra/.terraform.lock.hcl` exists and is tracked, copy it to `infra/chat/.terraform.lock.hcl` so the runner pins the same providers; otherwise leave none.

### Task 3: The owner's steps, per deployment, in this order

Not an agent's task. Recorded here so the sequence is one place.

1. Merge the pull request. The chat's deploy on `main` applies the module and fails at its live check; read the address in the apply log's `run_host` warning, or `terraform -chdir=infra/chat output service_url` locally after `init`.
2. Tell the agent the address; it opens the second pull request writing `run_host` into `chat/chat.json`. Merge it; the deploy passes.
3. In the Google Cloud console for the project: accept Claude's terms and enable Claude Sonnet 5 in Vertex AI's Model Garden; on the Quotas page, lower the Sonnet 5 quotas for the `eu` multi-region to about 60 requests and 300,000 input tokens a minute.
4. At Hostpoint, add the records `terraform -chdir=infra/chat output dns_records` prints for the chat's domain, as for the MCP host's. The certificate follows within the hour.
5. Send the README's one message and read `done.spent`; send a second within five minutes and see `spent` fall. Tell the agent what `GET https://<domain>/chat` reports as `address` from your own network, so the proxy-hop count can be confirmed.
6. In the repository's `protect-main` ruleset, add `chat / build` and `chat / terraform` to the required checks.
