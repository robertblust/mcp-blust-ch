# Parity report — the server against the skill bundle

The deployed server and the skill bundle are two surfaces of one commit of
`robertblust/mental-model`, `2fd146fe669ef80f7d7b8090ad1cf533b9020ebc`. The brief's acceptance
asks three questions of both and reports any difference as a model or projection defect,
never as something to fix in the server. This is that report, made on 2026-09-17.

## Method

The server was asked at its Cloud Run address, `https://mcp-6nrmpez2aq-oa.a.run.app/mcp`,
the address the deploy's own check uses, since the custom domain's certificate was still in
validation. The questions were put through the SDK client with this script, run from the
repository root so it resolves the client package:

```js
import { Client, StreamableHTTPClientTransport } from "@modelcontextprotocol/client";
const client = new Client({ name: "parity", version: "0" });
await client.connect(new StreamableHTTPClientTransport(new URL(process.argv[2])));
const call = async (name, args) => (await client.callTool({ name, arguments: args })).structuredContent;
const profile = await call("get_entity", { type: "profile", name: "Robert Blust" });
const expert = profile.entity.references.filter((r) => r.via === "Skills.Skill" && r.attrs.Level.name === "Expert");
console.log("COMMIT", profile.model.commit);
console.log("Q1 Expert skills:", expert.length);
for (const r of expert) console.log(" -", r.name, "|", r.attrs.Evidence);
const lm = await call("get_entity", { type: "experience", name: "Co-Founder & Head of Technology" });
console.log("Q2 LIKE MAGIC:", lm.entity.fields.organization, JSON.stringify(lm.entity.stamp));
console.log(lm.entity.sections.find((s) => s.heading === "Achievements")?.text);
const values = await call("list_entities", { type: "value" });
console.log("Q3 holds to:", JSON.stringify(values.entities.map((v) => v.name)));
await client.close();
```

The bundle was built from a fresh clone of the model checked out at the same commit, with
the model's own exporter:

```sh
git clone https://github.com/robertblust/mental-model /tmp/mm
git -C /tmp/mm checkout 2fd146fe669ef80f7d7b8090ad1cf533b9020ebc
cd /tmp/mm && python3 .claude/skills/companygraph-export/build.py
unzip dist/mm-skill.zip -d dist/skill
```

The bundle's `model/profiles.md`, `model/values.md` and the profile's experiences are the
bundle's side of each answer. Every answer the server gave carried the commit above.

## The connectors

ChatGPT's developer mode took `https://mcp.blust.ch/mcp` as a remote MCP server on
2026-09-17, once the domain's certificate was issued, and answered the owner's questions
from the server's tools. Claude took the same URL as a custom connector the same day and
answered likewise. The owner's verdict on both was that they work; both connect without
credentials, as the brief decided.

## Finding

No difference on any of the three questions. Nothing here is reported as a model or
projection defect, and nothing was changed in the server. The one thing the comparison
surfaced is not a difference but a shape: the bundle's exporter names its output after the
directory it runs in, so a clone called `mm` produced `mm-skill.zip` and the exporter's own
verify step, which expects `mental-model`, failed on the name alone. That belongs to the model
repository's exporter and is recorded, not fixed here.
